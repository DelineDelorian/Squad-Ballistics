# Выпуск обновления / Releasing

Автообновление в приложении работает так:

1. При запуске `.exe` читает `version.txt` из ветки **main**.
2. Если версия там **новее** `CURRENT_VERSION` в `updater.py`, скачивается
   `SquadBallistics.zip` из **последнего релиза** на GitHub и устанавливается.

Поэтому важен порядок: **сначала релиз с zip, потом `version.txt` в main.**
Если сделать наоборот, у всех пользователей скачается старый zip, и
обновление будет запускаться при каждом старте.

## Тестовая сборка (ничего не публикует)

* Локально: `build.bat` → `dist\SquadBallistics\SquadBallistics.exe`.
* Через GitHub: любой push в ветку запускает Actions → **build-windows**,
  готовый exe лежит в разделе **Artifacts** этого запуска.
  Релиз при этом не создаётся, пользователи ничего не получают.

## Публикация новой версии

1. Поднять версию в двух местах (тест проверяет, что они совпадают):
   * `version.txt` → например `1.2.0`
   * `updater.py` → `CURRENT_VERSION = "1.2.0"`
2. Закоммитить и запушить в рабочую ветку, дождаться зелёного **build-windows**.
3. Создать тег на этом коммите и запушить его:
   ```
   git tag v1.2.0
   git push origin v1.2.0
   ```
   Actions соберёт exe и опубликует релиз `v1.2.0` с `SquadBallistics.zip`.
4. Убедиться, что релиз появился и в нём есть `SquadBallistics.zip`.
5. Только после этого влить ветку в **main** (Pull Request → Merge).
   С этого момента пользователи начнут получать обновление.

Вручную без Actions: `build.bat`, затем на GitHub → Releases → *Draft a new
release*, тег `v1.2.0`, приложить `dist\SquadBallistics.zip`, опубликовать,
и после этого влить изменения в main.
